# 后台路径规划与 OpenMP

普通车辆入场现在支持 `ParkingService::enterAsync`。macOS 管理端的本地普通入场、TCP `enter`、REST `/api/enter` 和照片识别成功后的自动入场使用此接口。请求结果准备好后才回复调用方；协议字段与成功结果保持兼容。

## 执行流程

1. 在业务事件线程完成预约到期检查，复制布局、网格、车位状态、分配策略与权重。
2. 专用 `QThreadPool` 同时执行一个入场任务。工作线程只读取快照，不访问服务对象、界面或 SQLite 连接。
3. 可用时，通过 OpenMP 并行计算不同出入口到候选车位的路径，每个搜索仍一次覆盖全部候选目标。最多使用 4 个计算线程，受 `OMP_NUM_THREADS` 与出入口数量进一步限制。
4. 按原有出入口顺序归并路径和评分，保持并列选择和浮点累加顺序。
5. 回到业务事件线程，检查配置版本与车位状态。如果状态改变，重新取快照计算，最多重试 2 次；持续变化时返回错误。通过检查后才占位、更新预约与记录，并写入数据库。

队列最多容纳 8 个请求，包含正在计算的任务。超过上限时返回“路径规划繁忙，请稍后重试”；REST 使用 HTTP 503。队列逐个提交入场，避免同时抢占同一车位。请求上下文销毁后不执行回调、不提交该次入场；服务销毁时等待后台任务退出，工作线程不持有服务指针。

## 编译

`SMARTPARK_ENABLE_OPENMP` 默认开启。CMake 找到 OpenMP C++ 运行库时自动链接 `OpenMP::OpenMP_CXX`，配置输出为 `SmartPark route planning: OpenMP enabled`。

未找到 OpenMP 时，自动采用后台串行搜索，配置输出为 `SmartPark route planning: serial fallback (OpenMP not found)`。仍然在后台执行，因此普通入场搜索不会占用界面或网络事件线程。AppleClang 默认不附带 OpenMP，需要使用配置了 OpenMP 的工具链才能启用多线程搜索。

可用 `-DSMARTPARK_ENABLE_OPENMP=OFF` 显式关闭 OpenMP。运行时可设置 `OMP_NUM_THREADS=1` 限制为一个搜索线程；即使设置为更高值，应用仍最多使用 4 个。

## 范围与验证

保留同步 `enter`、预览、预约创建及显式预约到场接口，供现有同步业务使用。这些接口可能仍在调用线程计算路径。SQLite 提交仍在业务线程，本次没有将数据库操作移到后台，也没有改变车牌识别的进程调度。

新增 `smartpark_background_planning_tests` 覆盖队列上限、事件循环响应、重复车牌、计算期间配置和车位变化、请求上下文与服务销毁、预约到场，以及单线程与多线程配置下分配结果的一致性。有 OpenMP 时，一致性测试分别使用 1 和 4 个线程；无 OpenMP 时验证串行稳定性。

本次 macOS 完整构建通过，以下 6 组 CTest 全部通过：核心模型、后台规划、闸机补报、macOS 地图、macOS 远程管理端、REST/TCP 端到端。当前环境未找到 OpenMP，已验证后台串行回退；OpenMP 实际执行与提速幅度需要在有运行库的环境进一步测量。
