## 2.2.1 macOS 管理端功能需求

macOS 管理端是停车场日常运营的主要操作入口，供管理员在本机完成车位监控、车辆入离场办理、预约核销、记录查询与场地配置。与道闸终端、命令行用户端和网页端不同，管理端关注全场态势与异常处置，而不是单笔自助业务，因此功能需求围绕"看得见、办得动、查得回、配得准"展开。

在监控方面，管理端需要实时展示总车位、空闲车位、占用、预留、收入与分区压力等指标，并用场地平面图区分车位状态、显示入场与离场路线。在作业方面，需要支持按车牌办理入场并自动分配车位、按车牌结算离场、查看识别照片，以及在特殊情况下使用应急生命通道入场。在预约方面，需要创建时段预约、核对到场、取消并退定金，同时展示预约规则与历史预约。在查询与配置方面，需要按时间范围检索停车记录、查看计费规则，并编辑或导入场地布局。

系统需支持两种部署形态：本地模式直接调用同一套 C++ 核心服务并读写本机 SQLite 数据库；远程模式通过 TCP 连接统一服务端，由服务端提供车位快照、布局、记录与预约数据。远程模式下布局编辑、分配策略切换、应急入场与在场车型更正暂不提供，界面应避免出现无法完成的入口。无论采用哪种模式，界面都不重复实现业务规则，所有写操作均由核心层或服务端校验，并在成功后刷新相关页面。

## 3.1.2 macOS 管理端界面设计

管理端采用原生 AppKit 与 Objective-C++ 实现，界面由登录窗口、注册表单和主窗口三部分组成。主窗口使用"侧边栏 + 内容区"的分栏结构，七个业务页面共享同一个数据桥接对象；页面只负责展示与收集输入，业务判断全部交给桥接层。界面以半透明材质卡片承载层次，表格、按钮、日期选择器等均使用系统控件。

### 3.1.2.1 界面总体结构与导航

主窗口初始内容尺寸为 1120×720 点，最小 960×600 点；标题栏隐藏，页面标题与"刷新"按钮放在工具栏中（`MainWindowController.mm:90`、`:105`、`:315-323`）。窗口主体为 `NSSplitViewController`，左侧为不可折叠的侧边栏，宽度在 200 至 260 点之间；右侧是页面宿主 `PageHostViewController`，切页时替换其子视图控制器，子视图自适应填满内容区（`MainWindowController.mm:38-58`）。

侧边栏共七项：菜单、车位图、车辆出入库、当前车位、预约管理、停车记录、设施配置，每行高 40 点；底部固定显示"管理员：<账号>"和"退出登录"按钮（`SidebarViewController.mm:13`、`:99`、`:136`）。选中某行时，侧边栏通过代理方法 `sidebar:didSelectIndex:` 通知主窗口，主窗口调用 `showPage:` 切换页面并让该页重新取数，工具栏标题同步更新（`MainWindowController.mm:286-323`）。点击"退出登录"确认后返回登录窗口。

数据来源方面，主窗口创建一个 `ParkingBridge` 并注入所有页面，七页共享同一份布局与业务对象；任一页面完成写操作后发出 `SmartParkDataChanged` 通知，其余页面据此刷新（`MainWindowController.mm:302-310`）。这种结构避免各页各自建库或缓存，保证页面间数据口径一致。

### 3.1.2.2 登录与注册窗口

登录窗口为 420×494 点的无标题栏毛玻璃窗口，可拖动，内容是一张登录卡片（`LoginViewController.mm:137`、`AppDelegate.mm:123`）。卡片内自上而下依次为应用标题与副标题、账号输入框、密码输入框（带"显示密码"复选框）、"记住账号""记住密码"复选框、"连接远程服务端"复选框、远程地址与端口行、红色错误提示、登录按钮和"注册新账号"按钮，账号行与密码行宽 292 点，回车等同于点击"登录"。

本地模式用本机账号库校验账号密码，连续 5 次输错会锁定登录 30 秒，按钮标题逐秒显示"尝试过于频繁，N 秒后可重试"并禁用相关控件（`LoginViewController.mm:18-19`、`:527`、`:579`）。勾选"连接远程服务端"后地址行才显示，默认地址 10.108.17.55、端口 9527；登录时通过 `ServerSession` 连接服务端，在 8 秒内等待鉴权结果，超时或拒绝都会给出可读提示（`LoginViewController.mm:94-97`、`:436`）。"记住密码"把口令写入系统钥匙串，服务名为 `com.smartpark.admin.macos`，而不是普通配置文件（`LoginViewController.mm:369`）。

注册以 sheet 形式呈现在登录窗口之上，包含账号、密码与确认密码等字段，注册成功后自动回填账号并聚焦密码框（`RegisterViewController.mm:30`、`:154`）。登录与注册的数据来源都是本机 `UserStore`；远程账号校验由服务端完成，但本机账号库仍需可用，否则启动即报错退出（`AppDelegate.mm:90`）。

### 3.1.2.3 仪表盘页面

仪表盘是登录后的默认页面，整体是纵向可滚动的卡片流：顶部四张 KPI 卡（总车位、空闲、占用、预留），其下是一行文字摘要和四张快捷操作卡，再往下是三行、每行两张的图表面板，最底部是四条洞察提示（`DashboardViewController.mm:79-213`）。KPI 数值用 23 点等宽数字突出显示；快捷操作卡由标题、说明和"前往"按钮组成，依次为快捷入库、预约、出库、反向寻车（`DashboardViewController.mm:234`、`:287-323`）。

交互上，"快捷入库""出库"跳转车辆出入库页，"预约"跳转预约管理页；"反向寻车"弹出带在场车牌下拉框的对话框，确认后先切换到车位图页面，再发出寻车请求（`DashboardViewController.mm:331-388`）。图表包括车位组合环形图、分区压力柱状图、车流统计柱状图，以及近 7 天收入、近 7 天流量、占用率预测三条折线；占用率预测的纵轴为百分比且上限固定为 100（`DashboardViewController.mm:150-185`）。

数据来源为 `ParkingBridge` 的车位统计、停车记录、收入与洞察结果，`refreshMetrics` 一次算出全部数值与图表数据（`DashboardViewController.mm:406-648`）。当数据源能力不足时，相关卡片整块隐藏；例如远程模式下记录与定金明细由服务端持有，摘要文案会改为"远程服务端快照（快照时间）……"，避免展示不完整的数据（`DashboardViewController.mm:406-648`）。

### 3.1.2.4 停车地图页面

车位图页面分为三部分：顶部一行图例、一条"反向寻车"操作行，以及铺满剩余空间的场地平面图（`ParkingMapViewController.mm:34-109`）。图例说明"橙色框 = 已被预约（预约创建即锁位），悬停可看预约车牌与时段"；操作行由标题、可输入可选择的在场车牌下拉框、"开始寻车""清除路线"两个按钮和一行状态文字组成（`ParkingMapViewController.mm:37`、`:49`、`:60-64`）。

平面图由 `ParkingMapView` 自绘：先把布局文件的米制坐标等比缩放到视图坐标并留出 12 点边距，再绘制墙体（在入口、出口位置留缺口）、障碍、车位、入口与出口，以及入场、离场路线和反向寻车路线（`ParkingMapView.mm:112-126`、`:331`、`:452-487`、`:535-566`）。车位颜色区分状态与类型：占用为红色、预约为橙色、空闲为绿色、充电车位为蓝色、VIP 车位为紫色、停用为灰色；悬停时工具提示显示车位号、车牌或类型（`ParkingMapView.mm:282`）。

输入在场车牌并点"开始寻车"后，地图用灰色画出入口到车位、蓝色画出车位到最近出口的步行路线，状态行同时给出车位位置、步行距离与转弯数；点"清除路线"恢复初始提示（`ParkingMapViewController.mm:152`、`:208`、`ParkingMapView.mm:246`）。数据来源为桥接层的布局、车位、在场记录与寻车结果；页面刷新时只要求地图重绘并重新载入在场车牌，地图本身不保存业务状态（`ParkingMapViewController.mm:117`、`:138`）。

### 3.1.2.5 车辆作业页面

车辆作业页采用"表单—照片—结果"三段式布局：顶部是入离场表单卡，左下方是车牌照片预览卡，右下方是办理结果卡（`OperationsViewController.mm:94-306`）。表单包含车牌输入框、车辆类型下拉框（轿车、摩托车、卡车、电动车）和分配策略下拉框（加权代价（推荐）、最近车位）；按钮分两行，主行为"办理入场并分配车位""修改车辆类型""车辆出库"，次行为"识别并入场""识别并出场""取消识别""应急生命通道入场"，下方还有可展开的"评分明细"和状态提示（`OperationsViewController.mm:94-306`、`:410`、`:421`）。

办理入场时页面先做非空与并发校验，再按所选策略调用异步入场；成功后在状态行显示"入场成功：车牌 → 车位｜行驶距离、转弯数"，并在结果卡中填入车牌、车型、车位、入场时间等七项字段（`OperationsViewController.mm:339-409`、`:532`）。展开评分明细可看到入口距离、出口距离、周边占用数、分区压力、转向次数、类型成本与综合评分。办理离场会显示车位、时长与费用，并按 `PlatePhotoArchive` 把该车照片移入 `history/` 目录、按上下两个时间改名留存（`OperationsViewController.mm:446-520`、`PlatePhotoArchive.h:34`）。

图片识牌入口打开系统文件选择器，只接受 JPEG、PNG、BMP；本机 Python 识别服务返回车牌与裁剪图后，页面在照片卡中显示识别结果。识别置信度高于阈值（默认 0.85，可用环境变量 `SMARTPARK_LPR_CONFIRM_THRESHOLD` 覆盖）时直接办理，低于阈值则弹出确认框供人工核对（`OperationsViewController.mm:594`、`:906`、`:1006`）。远程模式下"应急生命通道入场"与"修改车辆类型"会提示当前模式不支持（`OperationsViewController.mm:425`、`:560`）。数据来源为 `ParkingBridge` 的入场、离场、车型修改、应急入场接口，识别由 `LocalRecognitionService` 启动的本机进程完成。

### 3.1.2.6 车位占用、预约管理与停车记录页面

三个页面都以系统表格为主体，共用同一个 `TableView` 封装：表头随列宽铺满，列宽不足时横向滚动，状态列使用胶囊徽章，整行悬停可看到完整文本（`TableView.mm:1-326`）。车位占用页把当前车位按列表展示，内容宽度小于 1000 点时用单表，否则左右两表各占一半，列为"车位/类型、状态、车牌、车辆类型、预约时段"（`OccupancyViewController.mm:47`、`:119`、`:138`）。选中一条"占用"记录后页面发出 `SmartParkVehicleSelected` 通知，车辆作业页据此预填车牌，可直接点"车辆出库"（`OccupancyViewController.mm:155`）。

预约管理页由表单卡和预约表格组成：表单含车牌、车辆类型、到场时间、时长（30 分钟至 4 小时）、"无障碍车位（免定金）"复选框，以及"创建预约""确认所选预约到场""取消所选预约"三个按钮（`BookingViewController.mm:45`、`:264`、`:334`、`:414`）。表格列为"编号、车牌、车位、创建时间、预约时间、宽限截止、定金(元)、状态、来源"，来源列区分"时段预约"与"预约(历史)"；选中一行会把车牌回填到表单，历史预约只允许查看（`BookingViewController.mm:206`、`:257`）。创建成功时页面显示分配到的车位、已收定金与预期入离场路线，并把路线交给地图绘制（`BookingViewController.mm:264`）。

停车记录页顶部是"时间范围 + 两个日期选择器 + 查询/显示全部"的筛选行，默认查询最近 7 天；表格列为"车牌、车辆类型、车位、入场时间、离场时间、时长(分钟)、费用(元)、状态"（`RecordsViewController.mm:30`、`:144`）。记录按时间区间重叠筛选而非严格包含，因此跨窗口的在停车辆也会被列出，汇总行给出结果条数、在停车辆数与费用合计；起始时间晚于结束时间时会提示"时间范围无效"（`RecordsViewController.mm:101`、`:125`）。三页数据均来自桥接层的车位、预约、规则与记录接口，写操作完成后发出 `SmartParkDataChanged` 通知刷新其它页面。

### 3.1.2.7 设置页面

设置页由两张卡片组成：上方是"停车场布局"编辑卡，下方是只读的"计费规则"卡（`SettingsViewController.mm:33-194`）。布局卡包含一段指令格式说明、一个高约 200 点且使用等宽字体的 `NSTextView`、状态标签，以及"应用布局""载入内置布局""还原修改""导入…""导出…"五个按钮；计费卡用一句话展示免费时长、计费单元、首单元费用、后续单元费用和单次封顶金额。

交互上，编辑布局文本会实时调用核心布局解析器校验语法：合法时显示"语法有效 · 将生成 N 个车位（尚未应用）"，非法时用红字给出语法错误（`SettingsViewController.mm:229-261`）。点击"应用布局"先弹确认框；若新布局与数据库保存的布局不匹配，会再次提示将清空历史停车记录与预约，确认后才重置数据库并应用（`SettingsViewController.mm:262-356`）。导入使用文本文件打开面板，导出默认文件名为 `smartpark-layout.txt`（`SettingsViewController.mm:376`、`:405`）。

数据来源为 `ParkingBridge` 的布局文本、应用布局与重置接口，页面不直接操作数据库；内存模式或数据库不可用时，应用结果会明确提示"仅保存在内存，重启后不会保留"（`SettingsViewController.mm:338`）。计费规则只做展示，不提供费率写入口（`SettingsViewController.mm:357`、`:365`）。

### 3.1.2.8 远程模式与数据源切换

管理端把数据来源抽象成 `ParkingDataSource` 接口，界面只依赖它的能力查询与读写方法（`bridge/ParkingDataSource.h:26-43`）。本地模式下 `ParkingBridge` 自己持有 `Persistence` 与 `ParkingService`，直接读写本机 SQLite；调用 `connectRemote()` 后，桥接对象把请求转交给 `RemoteDataSource`，由它通过 `ServerSession` 与 9527 端口的服务端通信（`bridge/ParkingBridge.h:24-26`、`:172`）。

模式切换发生在登录阶段：勾选远程并登录成功后，主窗口调用 `connectToRemoteHost:port:user:password:`，再根据服务端返回的能力位决定界面形态（`MainWindowController.mm:183-213`）。远程模式下预约、记录、定金、洞察等能力为真，而应急入场、在场车型更正、策略切换、布局编辑被标记为不可用；主窗口直接隐藏设施配置页，车辆作业页中的对应按钮会给出"远程模式不支持"的提示（`bridge/RemoteDataSource.mm:185-198`、`MainWindowController.mm:223-245`）。

| 能力 | 本地模式 | 远程模式 |
| --- | --- | --- |
| 车位图、入离场、时段预约、记录 | 支持 | 支持，数据来自服务端快照 |
| 布局编辑、分配策略切换 | 支持 | 不支持 |
| 应急入场、在场车型更正 | 支持 | 不支持 |
| 图片识牌 | 本机 Python 识别 | 本机 Python 识别（服务端识牌接口已实现，界面尚未接入远程识别） |

数据刷新采用"快照 + 事件"：远程数据源启动后请求 `admin.snapshot`，把布局、车位、记录、预约、预约规则、定金与 7 天收入缓存为只读快照；收到服务端事件后不维护增量状态，而是重新拉取整份快照再刷新页面（`bridge/RemoteDataSource.mm:140-143`、`:223-244`、`:257`）。写操作通过协议请求提交，由服务端校验并落库；断线后数据源自动重连并重新取快照，未获确认的写操作不自动重发（多端同步细节见 4.2.5 节）。运营分析接口 `analytics.report` 用于补充统计，洞察则在本地用同一套引擎计算（`bridge/RemoteDataSource.mm:245`、`:448`）。

## 4.1.1 macOS 管理端操作演示

以下步骤均在 macOS 本机执行，演示数据使用仓库自带的布局与演示账号。步骤中的车牌、车位与金额为示例含义，实际数值以运行结果为准。

### 4.1.1.1 启动、登录与本地/远程模式选择

1. 在仓库根目录执行 `scripts/build-macos.sh`；完成后可执行文件位于 `build/macos/apps/macos/smartpark_admin_macos.app/Contents/MacOS/smartpark_admin_macos`。
2. 本地模式执行 `scripts/run-macos.sh`；远程模式执行 `scripts/run-macos.sh --remote 127.0.0.1:9527 --user admin`，启动参数会预填远程地址与账号。
3. 在登录窗口输入账号 `admin`、密码 `smartpark`；如需连接远程服务端，勾选"连接远程服务端"并确认地址与端口，然后点击"登录"。
4. 预期：登录窗口关闭并出现主窗口，默认停在仪表盘，侧边栏底部显示"管理员：admin"；本地模式首次使用可先到"设施配置"核对或应用场地布局。
5. 若远程登录失败，错误标签会显示服务端返回原因；本地连续输错 5 次会锁定 30 秒，此时可点"注册新账号"创建新的本机账号。

### 4.1.1.2 仪表盘与实时车位图

1. 登录后观察仪表盘四张 KPI 卡与文字摘要，预期数值与当前车位状态一致；下方六张图表与四条洞察均可显示。
2. 点侧边栏"车位图"，预期显示场地平面图；把鼠标移到车位上，工具提示显示车位号、状态与车牌，已预约车位显示"已预约"与预约车牌。
3. 在"反向寻车"下拉框选择一辆在场车牌，点"开始寻车"；预期状态行显示"停在 X（Y 区）｜入口→车位 步行 N 米（K 个转弯）·车位→出口…"，地图同时出现灰色与蓝色路线。
4. 点"清除路线"，预期路线消失，状态行提示"已清除路线。"。
5. 若此时在道闸终端或网页端产生入场、离场，远程模式下管理端会随事件刷新；也可点工具栏"刷新"手动重取当前页数据。

### 4.1.1.3 车辆入场与车位分配

1. 点侧边栏"车辆出入库"，在车牌框输入测试车牌，类型选"轿车"，策略保持"加权代价（推荐）"。
2. 点"办理入场并分配车位"，预期状态行显示"入场成功：车牌 → 车位｜行驶 N 米、K 个转弯"，右侧结果卡填入车牌、车型、车位与入场时间。
3. 展开"评分明细"，预期显示入口距离、出口距离、周边占用数、分区压力、转向次数、类型成本与综合评分。
4. 切换到车位图，预期该车位变为占用色并出现入场与离场规划路线；到"当前车位"页应能查到该车牌。
5. 如需测试应急功能，点"应急生命通道入场"，预期系统分配一个可用车位并在状态行提示结果；远程模式下该按钮只给出不支持提示。

### 4.1.1.4 车辆离场与计费

1. 在"车辆出入库"页输入刚入场的车牌，或到"当前车位"页选中该车占用行，让车牌自动带入输入框。
2. 点"车辆出库"，预期状态行显示"离场完成：车牌｜车位｜时长｜费用"，结果卡中的出场时间、停车时长、应付款被填充。
3. 按默认计费规则核对金额：免费 30 分钟，超出部分按 30 分钟单元向上取整，首单元 5 元、后续每单元 5 元、单次封顶 100 元（`README.md:180`）。
4. 预期该车位在车位图与"当前车位"页恢复为空闲，"停车记录"页新增一条已结束记录，费用与时长与结算结果一致。
5. 若该车有识牌留档照片，预期状态行追加"车牌照片已移入 history"及文件名，照片默认出现在 `examples/platephoto/history/` 下。

### 4.1.1.5 预约管理与到场核销

1. 点侧边栏"预约管理"，填写预约车牌与车辆类型；到场时间默认是当前时间 45 分钟后并向上取整到 15 分钟，时长默认 2 小时，需要时勾选"无障碍车位（免定金）"。
2. 点"创建预约"，预期提示"预约成功：车牌 → 车位；定金 20.00 元已收"，并给出预期入离场路线与最晚到场时间，下表新增一行"时段预约"。
3. 切到车位图查看，预期该车位显示为橙色并带预约虚线；悬停可看到预约车牌与时段。
4. 回到预约管理页选中该行，点"确认所选预约到场"，预期提示到场成功、车位转为占用，并在停车记录中生成记录；定金将在离场时抵扣。
5. 若选另一条预约并点"取消所选预约"，预期提示取消成功、定金全额退回，车位恢复空闲。
6. 若提前量、时长或时间范围不满足默认规则，预期页面直接给出可读的拒绝原因，而不是静默失败。

### 4.1.1.6 图片识牌与人工核对

1. 在"车辆出入库"页点"识别并入场"，在弹出的文件面板中选择一张 JPEG、PNG 或 BMP 格式的车牌照片。
2. 预期右侧照片卡显示裁剪后的车牌区域，状态行显示识别车牌与置信度；识别成功且置信度不低于 0.85 时自动完成入场。
3. 置信度低于阈值时，预期弹出"识别置信度偏低"确认框并列出候选车牌，管理员比对照片后可确认办理或取消。
4. 点"识别并出场"可观察出库识别流程：预期先留档出库照片，再结算离场，照片移入 `history/` 并按停车时段改名。
5. 识别失败时，预期状态行提示"未识别到车牌"；若缺少 Python 依赖，会提示配置 `SMARTPARK_LPR_PY`、`SMARTPARK_OCR_PY` 与识别脚本路径。
6. 说明：服务端已经提供识牌接口（TCP 的 `lpr.recognize` 与 REST 的 `/lpr/recognize`），远程客户端只需上传照片、无需安装模型环境；但当前版本的车辆作业页把识别固定在本机 Python 执行（`apps/macos/OperationsViewController.mm:714`，统一走 `LocalRecognitionService`），远程模式下只有停车业务交给桥接对象。因此本次演示在本地与远程两种模式下都需要本机配置识牌环境，区别只在停车数据来自本机数据库还是服务端。

### 4.1.1.7 停车记录查询与运营图表

1. 点侧边栏"停车记录"，默认时间范围为最近 7 天，点"查询"，预期表格列出该区间记录，并给出条数、在停车辆数与费用合计。
2. 把起始时间调到结束时间之后点"查询"，预期弹出"时间范围无效"提示；点"显示全部"则展示全部记录与"全部停车记录：…"的汇总。
3. 在表格中悬停日期或车牌单元格，预期显示完整文本；表格为单选，便于核对单条记录。
4. 回到仪表盘查看车位组合、分区压力、近 7 天收入、车流统计与占用率预测等图表，点工具栏"刷新"可重新取数；远程模式下这些数据来自服务端快照。
5. 在"设施配置"页可查看当前计费规则；远程模式下该页被隐藏，布局修改需在服务端配置中完成。

macOS 管理端有两项原生测试注册到 CTest：`smartpark_macos_map_tests` 与 `smartpark_macos_remote_tests`，统一用 `ctest --preset macos-tests` 运行，也可单独运行测试二进制（`README.md:217-220`）。地图测试 `tests/macos_map_tests.mm` 覆盖坐标变换、离屏渲染与悬停交互：期望变换与 `ParkingMapView::mapTransform` 完全一致，离屏渲染校验地图尺寸、墙体像素与车位文字，悬停提示以"车位号 | "开头且移出后清空，预约车位提示中含"已预约"与车牌；此外还覆盖本地预约从创建、到场到生成记录的生命周期、布局文件往返、布局与数据库不匹配时 `ready()` 为假，以及照片归档与出库改名。

本报告不转述测试通过率与耗时，测试结论应以实际运行 `ctest` 或测试二进制后的输出为准；`smartpark_macos_remote_tests` 连接真实服务端时需 `--remote <host> <port> <user> [password]` 参数（`README.md:219-220`）。

## 附B macOS 端问题与经验

- AppKit 与 Qt 事件循环需要显式共存。管理端没有使用 `NSApplicationMain`，而是手工创建应用与 `QCoreApplication`，再用 0.01 秒的 `NSTimer` 定期调用 `processEvents`；缺少这一步时远程 `QTcpSocket` 会一直停在"正在连接"（`main.mm:114-119`）。
- 主菜单必须手工安装。程序以代码构建界面，若不通过 `SmartParkInstallMainMenu()` 建立"编辑"菜单，⌘C、⌘V、⌘X、⌘A、⌘Z 等标准快捷键会失效（`MainMenu.mm:1-77`）。
- 远程能力差异不能靠页面各自判断，否则容易出现"按钮按得动却没有反馈"。本项目把差异集中到 `Capabilities` 结构，页面按能力位整页隐藏或给出明确提示（`bridge/ParkingDataSource.h:28-40`、`bridge/RemoteDataSource.mm:185-198`）。
- 识牌是否自动办理只取识别置信度，不取检测置信度。样张上检测置信度常在 0.8 出头而识别置信度可达 0.99，若混用会造成误判；阈值默认 0.85，低置信度转人工核对（`RecognitionConfidence.h:1-14`、`OperationsViewController.mm:1006`）。
- 布局变更与数据库签名绑定。新布局与库中布局不匹配时不能静默套用，需要二次确认并清空历史停车记录与预约、保留账号，避免出现"布局换了但车位数据对不上"（`SettingsViewController.mm:262-356`）。
- 远程刷新选择整份快照而非增量状态机。事件到达后重新请求快照，虽然多一次往返，但两端状态不会因漏事件而漂移（`bridge/RemoteDataSource.mm:140-143`）。
