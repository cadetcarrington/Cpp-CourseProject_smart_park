关键业务流程

入库 macOS 管理端 / 网页端

  1. 拍照或输入车牌
  2. →
  3. 车牌识别（置信度 < 0.85 弹一次确认）
  4. →
  5. 车辆入场（写 parking_records）
  6. →
  7. SpotAllocator 选位：分区优先 + 出口系数加权
  8. →
  9. GridPlanner 生成入场路线
  10. →
  11. 照片留档 + 结果面板
  12. →
  13. EventHub → WebSocket 推送网页端

出库 macOS 管理端 / 网页端

  1. 车牌或再次识别
  2. →
  3. 找到在场记录与车位
  4. →
  5. Billing 计费（停车时长 × 费率）
  6. →
  7. 支付订单（模拟网关）
  8. →
  9. 释放车位 · 生成出库路线
  10. →
  11. 记录归档 · 报表与图表更新

反向寻车 车位图

  1. 选在场车牌（弹窗或下拉）
  2. →
  3. 入口 → 车位：灰色路线（四向 · 走车道中间）
  4. →
  5. 车位 → 出口：蓝色路线
  6. →
  7. 端点吸附车位边缘 · 拐角圆弧
  8. →
  9. 「清除路线」同时清掉规划路线叠层

预约 创建即锁位

  1. 选车位与时段（最长提前 7 天）
  2. →
  3. 创建预约 → 立即锁位（Reserved）
  4. →
  5. 到场确认 → 生成在场记录（Active）
  6. →
  7. 超时未到 → 爽约释放 + 押金处理

部署与通信

角色运行形态数据 / 依赖与本系统其它部分的连接
服务端 smartpark_server（s1 上由 start.sh 拉起） SQLite 库 + data/garage-3tower.txt + 静态页目录 TCP 9527 / HTTP 18080 / WS 18081，供 macOS 与网页端接入
macOS 管理端 smartpark_admin_macos.app（Qt 6.8.3 + AppKit） 本地模式用本地库与本地 LPR；远程模式连服务端 本地：直接调 ParkingService；远程：TCP v1 + REST
网页端 静态页（服务端 --web-root 直出） 浏览器内运行，无构建步骤 REST /api/v1/* + WebSocket /ws
车牌识别 Python：scripts/recognize_plate.py（检测 + OCR） ONNX 模型 + 运行缓存 由服务端 PlateRecognition 或 macOS 本地进程调用
