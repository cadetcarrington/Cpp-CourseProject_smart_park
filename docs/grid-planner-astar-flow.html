04A* 主循环

  • 从堆中弹出 f = g + h 最小的状态
  • 惰性删除：cost > bestCost 的过期堆项直接丢弃
  • 目标格首次结算 → 记录；全部目标结算 → break
  • 展开方向：8 向（四向模式 4 向），检查边界 / 障碍 / 切角
  • step = (步长 + 转弯罚分) × 拥堵系数
  • g 更优 ⇒ 更新 parent / bestCost，压入 g + h

↻ 主循环（步骤 04）反复执行：弹出 f 最小状态 → 过期检查 → 目标结算 → 展开 8 个方向 → 松弛并压堆；直到 open 为空或全部目标结算后进入步骤 06。

关键数据结构

  • bestCost[state] / parent[state]：按“状态”存而不是按格子，保证每格首个结算状态即最优
  • firstSettledState[cell] + firstSettledStamp：多目标提前终止与路线重建的落点
  • goalStamp[cell]：目标格去重；openSet：std::push_heap / pop_heap 二叉堆
  • SearchScratch（thread_local）：容量只增不减，generation 标记表示“本次搜索写过该槽位”，省掉每次 ≈1.3 MB 的分配与清零

分支与退化情况

  • 目标集合为空：h≡0，退化为单源全图 Dijkstra（保留给需要全场距离场的调用）
  • 四向行人模式 allowDiagonal=false：只展开上下左右 4 向，启发值用 Manhattan；状态空间仍按 8 向分配
  • 不可达：起点/目标无空闲格，或目标格全部不可达 → 空 Route
  • 多入口寻车：当前是每个入口各跑一次单源搜索后比较，不是一次多源 A*

性能与复杂度

  • 状态数 ≈ 格子数 × 8：真实车库 9,860 格 → 78,881 状态
  • 最坏复杂度同 Dijkstra O(E log V)；h 越紧扩展越少
  • 启发表一次预计算 O(格子数 × 目标数) —— 多目标批量调用的主要开销
  • 惰性删除替代 closed 数组；配合 scratch 复用：Release 快 6–15%，Debug 寻车串行快约 2.7×
  • A* 相比 Dijkstra 单目标显著更快（行人单目标规划 736→84 µs 量级）
