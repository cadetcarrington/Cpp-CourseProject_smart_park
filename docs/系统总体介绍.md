# SmartPark 智能停车场管理系统总体介绍（管理员端）

## 1. 系统定位

SmartPark 是一个面向停车场管理员的综合管理系统。它把停车场日常工作集中到一个管理端中：管理员可以登录系统，查看当前车位情况，观察车辆进出，处理预约，查询停车记录，了解收入和利用率，并维护停车场的布局和运行参数。

系统的核心目标是让管理员清楚地知道“停车场现在是什么状态、刚刚发生了什么、接下来需要处理什么”。它既支持在一台 macOS 电脑上管理本地数据，也支持连接到独立运行的停车场服务器，适合演示环境和实际的集中式管理环境。

从使用者角度看，管理员端主要完成以下工作：

- 登录并进入停车场管理主界面；
- 查看总车位、空闲车位、已占用车位和预约车位；
- 在地图上直观看到停车场区域、车位、入口、出口和障碍物；
- 查看车辆入场、离场、当前停车和历史记录；
- 管理车辆预约和预约状态；
- 查看收入、停车时长、分区使用情况等运营信息；
- 进行停车场布局、数据连接和识别服务配置；
- 在需要时使用车牌照片识别车辆信息，并进行人工核对。

## 2. 系统由哪些部分组成

项目可以理解为“一个管理端、一个停车服务中心、若干现场终端和一套识别/测试工具”。

### 2.1 管理员端

管理员端位于 `apps/macos`，采用 macOS 原生界面。它负责显示页面、接收管理员操作，并把操作交给本地业务服务或远程停车服务器处理。管理员不需要直接操作数据库，也不需要了解车位分配、路径计算等内部规则。

### 2.2 停车业务中心

停车业务中心位于 `src/core`。它统一负责停车场的布局、车位、车辆、停车记录、预约、计费、统计和数据保存。无论操作来自管理员端、道闸设备还是网页端，最后都要经过这套业务中心，因此不同入口看到的停车状态能够保持一致。

### 2.3 服务端和现场终端

网络部分位于 `src/network`，服务端程序位于 `apps/server`。服务端统一保存数据，并同时为管理员端、道闸终端、用户终端和网页提供服务。

道闸程序位于 `apps/gate`，负责入口和出口的实际放行；用户命令行终端位于 `apps/user`，用于模拟车主查询和预约。它们与服务器通信，服务器再调用核心停车业务。

### 2.4 识别、训练和测试工具

车牌识别及相关脚本位于 `scripts`。它们可以从车牌照片中得到车牌号，或者作为服务器的识别服务运行。`tests` 保存核心业务、网络通信、管理员地图、识别流程和端到端测试。`docs` 保存部署、接口、识别和研究说明。

## 3. 管理员端的使用流程

### 3.1 启动和登录

程序从 `apps/macos/main.mm` 启动，由 `apps/macos/AppDelegate.h` 和 `apps/macos/AppDelegate.mm` 管理应用生命周期。启动时可以指定远程服务器、用户名、本地数据库和布局文件。`AppDelegate` 负责在登录页面和主窗口之间切换，用户通过认证之前不会进入业务页面。

登录页面由 `apps/macos/LoginViewController.h` 和 `apps/macos/LoginViewController.mm` 实现。新账号注册由 `apps/macos/RegisterViewController.h` 和 `apps/macos/RegisterViewController.mm` 实现。管理员登录后，系统会根据当前是本地模式还是远程模式，选择对应的数据来源。

如果选择“记住密码”，项目将密码交给 macOS 钥匙串保存，而不是直接写入普通配置文件。登录信息和权限由核心层的 `src/core/service/UserStore.h` 与 `src/core/service/UserStore.cpp` 统一管理。

### 3.2 主窗口和页面导航

`apps/macos/MainWindowController.h` 与 `apps/macos/MainWindowController.mm` 负责创建主窗口和各个业务页面。`apps/macos/SidebarViewController.h` 与 `apps/macos/SidebarViewController.mm` 负责左侧导航栏、当前账号显示和退出登录。

管理员进入系统后，通常可以在以下页面之间切换：

- 仪表盘：快速查看停车场当前总体情况；
- 停车地图：查看停车场空间布局和车位状态；
- 车辆作业：处理车辆入场、离场和相关操作；
- 车位占用：查看各区域的占用变化；
- 预约管理：查看、确认、取消和处理预约；
- 停车记录：查询车辆和历史停车信息；
- 系统设置：维护数据连接、布局和相关运行选项。

远程模式下，如果某些页面没有远程数据支持，侧边栏会隐藏这些页面，避免管理员进入空白页面。这部分由 `SidebarViewController` 的页面可见性控制完成。

### 3.3 仪表盘

仪表盘由 `apps/macos/DashboardViewController.h` 和 `apps/macos/DashboardViewController.mm` 负责。它将停车场的关键情况集中展示，例如总车位、当前占用、空闲数量、预约数量、收入、平均停车时长和分区压力。

图表控件分别位于：

- `apps/macos/DonutChartView.h`、`apps/macos/DonutChartView.mm`：展示占用与空闲比例；
- `apps/macos/BarChartView.h`、`apps/macos/BarChartView.mm`：比较各区域或各时段数据；
- `apps/macos/LineChartView.h`、`apps/macos/LineChartView.mm`：展示一段时间内的占用变化趋势；
- `apps/macos/TableView.h`、`apps/macos/TableView.mm`：展示记录、预约或统计明细。

这些页面主要帮助管理员做判断。例如，某个区域持续接近满位时，管理员可以提前关注车辆疏导；某个区域长期空闲时，可以检查布局或引导策略是否合理。

### 3.4 停车地图

停车地图由 `apps/macos/ParkingMapView.h`、`apps/macos/ParkingMapView.mm`、`apps/macos/ParkingMapViewController.h` 和 `apps/macos/ParkingMapViewController.mm` 实现。

地图会按照停车场布局显示场地、区域、车位、入口、出口和障碍物。车位状态用不同颜色或状态表示，管理员可以快速判断某个位置是否空闲、已占用、已预约或暂不可用。地图页面还可以展示车辆前往车位或离开停车场的大致路线。

地图使用的布局来源可以是本地布局文件，也可以是服务器返回的布局快照。布局文件中的区域、车位类型和障碍物会先由核心业务层检查，确认布局有效后再交给管理端显示。

### 3.5 车辆作业

车辆作业页面由 `apps/macos/OperationsViewController.h` 和 `apps/macos/OperationsViewController.mm` 实现。它是管理员处理车辆进出场的主要页面。

车辆到达时，系统可以根据车牌号或车牌照片查找车辆。如果车辆已有预约，系统会优先核对预约并使用对应车位；普通车辆则根据车位类型、距离、区域压力和当前占用情况推荐车位。管理员确认后，系统登记入场并更新车位状态。

车辆离场时，系统查找该车辆的停车记录，根据停车时长计算费用，完成离场登记并释放车位。涉及预约的车辆还会处理定金抵扣、退款或未到场处理。成功完成后，仪表盘、地图、记录列表和其他连接端都会同步更新。

### 3.6 车位占用和运营状态

`apps/macos/OccupancyViewController.h` 与 `apps/macos/OccupancyViewController.mm` 负责更集中地查看车位占用情况。它适合管理员观察各个区域的空闲量、占用量和变化趋势。

核心层的 `src/core/service/AnalyticsEngine.h/.cpp` 和 `src/core/service/ParkingInsightEngine.h/.cpp` 会从停车记录和当前车位状态中生成运营分析。分析内容包括高峰时段、区域压力、未来一段时间的占用趋势、长时间停车和充电车位使用情况。管理员可以把这些信息用于现场调度和运营安排。

### 3.7 预约管理

`apps/macos/BookingViewController.h` 与 `apps/macos/BookingViewController.mm` 负责预约相关页面。管理员可以查看预约车辆、预约时间、车位、定金和当前状态。

项目同时支持较简单的锁位预约和带时间段的预约。预约车辆在规定时间到场后，管理员确认入场；超过宽限时间仍未到场的预约会被标记为未到场，车位和定金按照规则处理。预约取消、退款、定金扣除和车位释放由核心业务层统一完成，管理员端主要负责查看和发起操作。

### 3.8 停车记录

`apps/macos/RecordsViewController.h` 与 `apps/macos/RecordsViewController.mm` 负责记录查询。管理员可以按车牌、时间和状态查看车辆记录，区分正在停车的记录和已经结束的记录，并查看入场时间、离场时间、停车时长、车位和费用。

记录最终由 `src/core/persistence/ParkingRepository.h/.cpp` 保存到 SQLite。管理端显示的数据可能来自本地数据库，也可能来自服务器返回的快照，但两种模式都通过同一套业务规则组织。

### 3.9 设置和系统配置

`apps/macos/SettingsViewController.h` 与 `apps/macos/SettingsViewController.mm` 负责配置页面。管理员可以在这里检查本地数据库、布局文件、服务器地址和识别服务等运行选项。

`apps/macos/TextUtil.h` 提供界面中常用的文本处理功能。`apps/macos/RecognitionConfidence.h` 用于整理识别置信度信息，提示管理员哪些识别结果需要人工复核。

## 4. 管理端如何取得数据

管理员端通过桥接层把界面和停车业务连接起来：

- `apps/macos/bridge/ParkingBridge.h` 与 `apps/macos/bridge/ParkingBridge.mm`：把 macOS 界面操作转换为停车业务操作；
- `apps/macos/bridge/ParkingDataSource.h`：定义管理端需要的数据来源；
- `apps/macos/bridge/RemoteDataSource.h` 与 `apps/macos/bridge/RemoteDataSource.mm`：连接远程服务器并接收数据；
- `src/network/ServerSession.h/.cpp`：负责远程登录、心跳、断线重连和异步请求。

本地模式下，管理端可以直接使用本地的核心服务、SQLite 数据库和布局文件。远程模式下，管理端通过服务器获得车位快照、布局、停车记录、预约和统计信息。管理员端不直接修改远程数据库，而是把操作发送给服务器，由服务器统一校验和保存。

服务器状态变化会通过事件通知管理端。例如道闸完成车辆入场后，服务端会发出入场事件，管理端收到后刷新地图、仪表盘和记录页面。远程连接断开时，系统会自动尝试重新连接；已经发出的写操作不会因为不确定结果而自动重复提交，避免重复入场或重复扣费。

## 5. 从管理员操作到业务结果

一次普通车辆入场大致经过以下步骤：

1. 管理员在车辆作业页面输入车牌，或导入车牌照片；
2. 系统识别或确认车牌，并检查车辆是否已有预约；
3. 业务中心根据当前布局和车位状态推荐可用车位；
4. 管理员确认后，车位变为已占用，同时生成停车记录；
5. 地图、仪表盘、占用统计和其他终端收到最新状态。

一次车辆离场大致经过以下步骤：

1. 管理员根据车牌找到当前停车记录；
2. 系统根据停车时间计算费用；
3. 如存在预约定金，则按规则抵扣、退款或结算；
4. 记录关闭，车位恢复为空闲；
5. 收入、记录、地图和统计页面刷新。

一次预约处理大致经过以下步骤：

1. 查看预约车辆和时间；
2. 系统检查时间范围、车位类型和已有预约冲突；
3. 预约成功后保留相应的预约信息；
4. 车辆到场时确认入场，未到场时按规则处理；
5. 车辆离场后完成定金和停车费用结算。

## 7. 数据和安全方面的基本设计

系统使用 SQLite 保存停车数据、预约、支付流水和审计记录。服务器负责统一保存远程数据，管理端不直接修改服务器数据库。用户登录后才能访问受保护的业务功能，管理员、道闸和普通用户具有不同权限。

停车场的重要操作会留下审计记录，例如车辆入场、车辆离场、预约操作和应急处理。审计记录带有前后关联关系，便于发现记录是否被异常修改。

车牌照片属于需要谨慎处理的信息。真实识别依赖外部模型和 OCR 环境，识别结果中的“格式正确”只代表它像一个合法车牌，并不等于识别结果一定正确。因此管理端保留置信度提示，重要业务应由管理员确认。识别并出入库时，管理端会把当次识别用的车牌裁剪图留档在仓库的 `examples/platephoto/`（车辆在场期间文件名是“车牌_入库时间”）；车辆出库后，这次停车的照片改名为“车牌_入库时间_出库时间”并移入 `examples/platephoto/history/`，方便按车牌和时段回溯。该目录是运行时产物，照片不纳入版本库（只保留说明文件 `examples/platephoto/README.md`）。

## 8. 构建和运行方式

项目使用 CMake 构建，要求 CMake 3.21 或更高版本、Qt6 和 C++17。顶层 `CMakeLists.txt` 会根据平台构建核心库、网络库、服务器、道闸、用户终端；在 macOS 上打开 `SMARTPARK_BUILD_MACOS_ADMIN` 时额外构建管理员端。

常用的管理员端开发流程是：

```bash
cmake --preset macos-debug -DCMAKE_PREFIX_PATH=<Qt安装路径>
cmake --build --preset macos-debug
ctest --preset macos-tests
```

也可以使用 `scripts/build-macos.sh` 构建，再使用 `scripts/run-macos.sh` 启动。远程服务器通常使用 `server-debug` 或 `server-release` 预设启动，管理端通过服务器地址连接。

真正的车牌识别还需要准备模型、PaddleOCR 和对应的 Python 环境。没有这些外部资源时，系统可以使用模拟识别或跳过相关测试，但不能把模拟结果当作真实识别精度。

## 9. 需要注意的边界

- 管理端主要负责展示和发起操作，车位分配、计费、预约和数据一致性由核心业务统一决定。
- 本地模式和远程模式的数据来源不同，远程模式需要服务器正常运行并完成登录。
- 服务器布局与数据库中的布局签名必须匹配；更换布局后不能直接沿用不匹配的数据。
- 真实车牌识别依赖外部模型、OCR 组件和 Python 环境，识别失败时需要管理员人工处理。
- 道闸支持断网后暂存进出场事件并在恢复连接后补报，但服务器仍会对重复事件进行检查。
- `server-release` 预设关闭测试，发布运行前应使用 debug 预设完成测试。
- 当前部分示例图片说明和实际目录结构可能存在差异；部署或演示时应以仓库当前文件和实际构建结果为准。

## 11. 按文件逐项说明

下面按“文件夹—文件”的顺序说明项目中主要源码、配置、脚本和测试文件。`.h` 文件主要放类、数据结构和接口声明，`.cpp`/`.mm` 文件负责具体实现；同名的 `.h` 和 `.cpp` 应当作为一个功能文件一起阅读。

### 11.1 根目录文件

- `CMakeLists.txt`：整个项目的总构建入口。检查 Qt6，规定 C++17，决定是否构建 macOS 管理端，并把 `src/core`、`src/network`、各个 `apps` 和 `tests` 加入构建。
- `CMakePresets.json`：保存三套常用构建方案：`macos-debug` 构建管理员端和测试，`server-debug` 构建服务端、终端和测试，`server-release` 构建发布版服务端。
- `README.md`：项目入口说明，包含安装依赖、构建、启动、服务器参数、车牌识别和常用测试命令。
- `handoff.md`：项目交接记录，说明历史实现、已知命令和需要结合当前源码确认的内容。
- `.gitignore`：规定构建目录、数据库、模型、训练结果和本地环境等不纳入版本管理。
- `my-layout.txt`：示例停车场布局描述文件。
- `garage-3tower-preview.png`、`garage-3tower-vs-drawing.png`：停车场布局的预览图和对照图，不参与业务运行。

### 11.2 `src/core/model`：停车场基础数据文件

- `Geometry.h`：定义点、矩形、距离、包含关系和矩形重叠判断，是布局和路径计算共用的几何基础。
- `ParkingLayout.h/.cpp`：读取和检查停车场布局，生成区域、车位、入口、出口和障碍物。`fromDescription` 读取文本布局，`fromParts` 接收服务器传来的布局快照。
- `ParkingSpot.h/.cpp`：表示单个车位，保存车位编号、区域、类型和状态，并处理占用、预约、释放、禁用和预约过期。
- `Vehicle.h/.cpp`：表示车辆，保存车牌号和车辆类型，例如普通汽车、摩托车、卡车和电动车。
- `ParkingRecord.h/.cpp`：表示一次实际停车记录，记录车牌、车位、入场时间、离场时间、车型和费用。
- `Booking.h/.cpp`：实现较简单的传统预约，状态包括已预约、已到场、未到场和已取消。
- `Reservation.h/.cpp`：实现带开始时间和结束时间的时段预约，另外保存定金、退款、扣除和预约路线等信息。

### 11.3 `src/core/service`：停车业务文件

- `ParkingService.h/.cpp`：核心业务总协调者。它统一处理车辆入场、离场、车位释放、传统预约、统计查询、数据恢复和异常回滚。
- `GridPlanner.h/.cpp`：在停车场网格上计算车辆或行人路线，避开障碍物和被占用区域。
- `SpotAllocator.h/.cpp`：根据车位类型、入口距离、出口距离、区域压力和拥堵程度推荐车位。
- `Billing.h/.cpp`：按照免费时长、计费单位、最低费用、单日上限计算停车费。
- `ReservationService.h/.cpp`：处理时段预约的创建、确认、取消、未到场、锁位和定金结算。
- `FakePaymentGateway.h/.cpp`：模拟支付、退款、扣除定金，主要用于演示和测试。
- `AuditLogService.h/.cpp`：记录车辆进出、预约、应急处理等重要操作，并维护可检查的审计链。
- `UserStore.h/.cpp`：管理账号、密码、角色、登录失败次数、令牌和登录有效期。
- `AnalyticsEngine.h/.cpp`：根据历史停车数据生成总体运营分析，例如占用率、收入、平均时长和高峰趋势。
- `ParkingInsightEngine.h/.cpp`：根据区域压力、近期进出速度和预约情况生成风险提示和运营建议。
- `RemoteAnalystClient.h/.cpp`：预留远程分析接口，只发送汇总后的指标和趋势数据。
- `DemoDirector.h/.cpp`：提供一套虚拟时间演示剧本，自动演示车辆入场、预约、离场和统计分析。
- `TimeUtil.h`：统一处理业务时间范围和 SQLite 中的毫秒时间转换。

### 11.4 `src/core/persistence`：数据保存文件

- `DatabaseManager.h/.cpp`：创建、打开和关闭 SQLite 数据库连接。
- `Persistence.h/.cpp`：组合数据库管理器和停车场数据仓库，负责初始化数据库和创建表结构。
- `ParkingRepository.h/.cpp`：真正读写车位、停车记录、布局、预约、定金流水和审计数据，并通过事务保证数据一致。

### 11.5 `src/network`：通信和服务端共用文件

## 12. 文件之间的主要工作流

### 12.1 管理员启动工作流

`main.mm` → `AppDelegate` → `LoginViewController` → `UserStore`/远程登录 → `MainWindowController` → `SidebarViewController` → 各业务页面。

本地模式中，页面通过 `ParkingBridge` 访问核心服务；远程模式中，页面通过 `RemoteDataSource` 调用 `ServerSession`，再由网络层访问服务器。

### 12.2 车辆入场工作流

`OperationsViewController` 接收车牌 → `LocalRecognitionService` 或服务器 `PlateRecognition` 得到识别结果 → `ParkingBridge`/`RemoteDataSource` 发起入场请求 → `ParkingService` 检查预约并调用 `SpotAllocator` → `GridPlanner` 计算路线 → `ParkingSpot` 改为占用 → `ParkingRecord` 建立记录 → `ParkingRepository` 保存 → `EventHub` 通知地图、仪表盘和其他终端。

如果车辆从真实入口进入，顺序是 `apps/gate/main.cpp` → `TcpClient` → `SmartParkTcpServer` → `ParkingService`，道闸收到成功响应后由 `BarrierGate` 执行开闸。

### 12.3 车辆离场工作流

管理员端或道闸发送离场请求 → `ParkingService` 找到活动停车记录 → `Billing` 计算费用 → `ReservationService` 处理预约定金 → `ParkingRepository` 在事务中关闭记录并释放车位 → `AuditLogService` 写入审计 → `EventHub` 推送状态变化。

### 12.4 预约工作流

`BookingViewController` → 管理端数据桥接 → `ReservationService` 检查时间和冲突 → `SpotAllocator` 选择合适车位 → `FakePaymentGateway` 处理演示定金 → `ParkingRepository` 保存预约 → 到场时转入 `ParkingService` 入场流程，未到场时释放车位并按规则处理定金。

### 12.5 远程实时刷新工作流

服务器收到 TCP 或 REST 操作 → `ParkingService` 完成修改 → `EventHub` 发布事件 → TCP 客户端、WebSocket 和 `ServerSession` 收到事件 → `RemoteDataSource` 更新数据 → 地图、仪表盘、表格页面重新显示。

### 12.6 断网补报工作流

道闸发现服务器不可用 → `OfflineQueue` 将车辆事件写入本地 JSONL → 道闸按本地规则放行 → 网络恢复后 `gate.replay` 批量发送 → `SmartParkTcpServer` 按车牌、事件类型和原始时间去重 → 只确认已经处理的连续前缀 → 道闸保留未确认后缀，等待下一次补报。

## 16. 代码级模型与核心服务

本节开始进入源码级说明。`.h` 是接口和数据结构契约，`.cpp` 是状态变化、校验和事务实现。修改公共枚举、函数参数或 JSON/数据库字段时，必须沿调用链同步修改。

### 16.1 `src/core/model/Geometry.h`

定义 `Point { double x{0.0}; double y{0.0}; }` 与 `Rectangle { Point origin; double width; double height; }`。`distance(Point,Point)` 用 `hypot` 计算距离；`Rectangle::contains(Point) const noexcept` 判断边界包含；`center() const noexcept` 返回中心；`rectanglesOverlap(Rectangle,Rectangle) noexcept` 仅在横向和纵向重叠都大于 `1e-9` 时判定冲突。它被布局、路径、分配和地图共同使用，改容差或边界规则会改变车位可达性、布局合法性和所有距离评分。

### 16.2 `src/core/model/Vehicle.h/.cpp`

定义 `VehicleType { Car, Motorcycle, Truck, Electric }`。`Vehicle(std::string,VehicleType)` 保存车牌和车型，空车牌抛出 `invalid_argument("车牌不能为空")`；`plateNumber() const noexcept` 和 `type() const noexcept` 只读返回字段。该类型进入车位、记录、预约、数据库和 TCP JSON。增加车型必须同步 Protocol 字符串转换、Repository 枚举校验、管理员下拉框和测试。

### 16.3 `src/core/model/ParkingSpot.h/.cpp`

定义 `SpotStatus { Available, Occupied, Reserved, Disabled }`、`SpotType { Normal, Accessible, Charging, Vip }`，以及 `ParkingSpot::Geometry { string zone; int row; int column; Rectangle bounds; Point accessPoint; SpotType type; }`。

主要接口：`ParkingSpot(string)`、`ParkingSpot(string,Geometry)`；查询 `identifier/status/type/isAvailable/parkedVehicle/geometry/bounds/accessPoint/zone/row/column/reservationExpiresAt`；变更 `occupy(const Vehicle&)`、`reserve(const Vehicle&,TimePoint)`、`expireReservation(TimePoint)`、`release() noexcept`、`disable() noexcept`；私有 `clearOccupancy() noexcept`。

规则是：`occupy` 允许 Available，Reserved 只能由同车牌转 Occupied；`reserve` 只能锁 Available；过期只释放 Reserved；`release` 只释放 Occupied/Reserved；`disable` 只允许 Available。改状态机要同步 ParkingService、ReservationService、数据库整数编码、地图状态颜色和所有状态测试。

### 16.4 `src/core/model/ParkingRecord.h/.cpp`

`ParkingRecord(string plate,string spot,TimePoint entry,VehicleType=Car)` 保存一次停车。查询有 `plateNumber/spotId/entryTime/exitTime/vehicleType/isClosed/duration/fee`，结束函数为 `close(TimePoint exitTime,double recordFee=0.0)`。构造拒绝空 plate/spot；close 拒绝重复关闭、早于入场的时间、负数或非有限费用；未关闭记录的 duration 使用当前时间。改 duration 或 close 会改变计费、收入、离场事务、分析和远程记录。

### 16.5 `src/core/model/Booking.h/.cpp`

传统预约状态是 `Booked/CheckedIn/NoShow/Cancelled`。`BookingPolicy` 默认定金 20、提前 7 天、宽限 30 分钟。构造函数为 `Booking(string id,string plate,string spot,TimePoint created,TimePoint arrival,TimePoint deadline,double deposit,BookingStatus=Booked)`；查询 `id/plateNumber/spotId/createdAt/arrivalTime/arrivalDeadline/deposit/status/isActive`；状态函数 `checkIn()`、`markNoShow()`、`cancel()`，只有 Booked 可迁移。ParkingService 的 create/confirm/expire/cancel 和 Repository bookings 表都依赖这个状态机。

### 16.6 `src/core/model/Reservation.h/.cpp`

新版预约状态为 `PendingPayment/Confirmed/CheckedIn/Completed/Cancelled/NoShow/Expired`，定金状态为 `Pending/Refunded/Forfeited/Applied`。`ReservationRule` 包含 maxAdvanceDays、minLeadTime、minDuration、gracePeriod、lockLeadTime 和 deposit。`DepositPayment` 记录 Charge/Refund/Forfeit/Apply 交易。

`ExpectedRoute` 保存 entranceIndex、exitIndex、entryRoute、exitRoute；`encode()` 生成 v1 文本，`decode()` 校验版本、数字和最多 100000 个点。`Reservation` 的构造函数还保存 accessible 标志和 chargeTransactionId；状态函数是 `checkIn/complete/cancel/markNoShow/expire/setDepositState`。合法迁移是 Confirmed→CheckedIn→Completed，Confirmed/Pending→Cancelled，Confirmed→NoShow，Pending→Expired。改状态或路线编码必须同步 ReservationService、ParkingRepository、TCP/REST payload 和 BookingViewController。

### 16.7 `src/core/model/ParkingLayout.h/.cpp`

定义 `AisleSide {Left,Right,Up,Down}`、`LayoutObstacle{name,bounds}`。入口函数有 `defaultLayout()`、`garageDescription()`、`garageLayout()`、`fromDescription(string)`、`fromParts(...)`；查询有 spots、regions、obstacles、siteWidth、siteHeight、entrances、exits、entrance、exit；内部 `addRegion(...)` 按行列和通道方向生成车位，`addObstacle(...)` 校验障碍。

布局文本支持 site/entrance/exit/region/obstacle，要求至少 10x10、一个入口、一个出口和一个区域，并拒绝越界、重叠和过窄通道。修改生成规则会同时改变车位几何、GridPlanner 阻塞、SpotAllocator 评分、管理员地图和 SQLite layout signature。

### 16.8 `src/core/service/GridPlanner.h/.cpp`

定义 `Route { vector<Point> points; double distance; double cost; int turnCount; }` 与 `OccupancyField { vector<int> occupancy; double weight{.35}; }`。构造函数为 `GridPlanner(double siteWidth,double siteHeight,const vector<ParkingSpot>&,const vector<Rectangle>&={},double cellSize=.5)`。

公开函数 `buildOccupancy(spots,radius=12,weight=.35)`、`plan(start,goal,field)`、`planFromToTargets(start,targets,field)`；私有函数族包括 columns/rows/cellIndex/cellCenter、nearestFreeCell、isFree、occupancyMultiplier、searchFromGoals、searchFrom、reconstruct。算法用八邻域搜索，避开车位和障碍中心格，禁止从两个阻塞格夹角穿过，代价含距离、0.35×cellSize 转弯惩罚和附近占用倍率。改 cellSize、阻塞规则或代价，会改变所有路线和车位推荐。

### 16.9 `src/core/service/SpotAllocator.h/.cpp`

策略为 `AllocationStrategy {WeightedCost,Nearest}`。`AllocationWeights` 含 entryPath、exitPath、laneCongestion、turnCount、typePenalty、occupancyRadius、occupancyK、zonePressure、exitCoefficients；`ScoreBreakdown` 保存各分项；`AllocationProposal` 保存候选车位、两条 Route、分数、附近占用数和门索引。

公开构造 `SpotAllocator(const ParkingLayout&,const GridPlanner&)`，策略/权重 getter/setter，以及 `propose(const Vehicle&,const vector<ParkingSpot>&,const string& requiredSpotId={}) const`。内部 `evaluateCandidates`、`exitCoefficient`、`makeScore`、`typePenaltyFor`、`nearbyOccupiedSpots` 完成评分。WeightedCost 综合入口、出口、拥堵、转弯、车型和区域压力；Nearest 只看入口距离。改权重即可改变运行策略；增加策略要同步 ParkingService、预约服务、设置页面和接口。

### 16.10 `src/core/service/ParkingService.h/.cpp`

这是停车业务聚合根，持有 layout、spots、车辆 planner、行人 planner、allocator、records、bookings、repository、billing 和 ReservationService。公共函数包括 `reserve`、`enter`、`emergencyEnter`、`leave`、`allocate`、`previewAllocation`、`cancelReservation`、`release`、`updateVehicleType`、`createBooking`、`confirmBooking`、`cancelBooking`、`expireReservations`、`expireBookings`、`findCar`、`remaining`、`occupied`、`reserved`、`records`、`activeRecord`、`totalRevenue`。

构造时 `ensureReachable` 检查所有车位从入口到出口可达。`enter` 优先核销预约，否则分配车位并创建 ParkingRecord；`leave` 调 Billing、ReservationService 和 Repository；`emergencyEnter` 可按出口距离驱逐最近车辆；`findCar` 使用不把车位当障碍的行人 planner。所有写操作都遵循“先改内存、再数据库事务、失败回滚”。改此文件会影响 GUI、TCP、REST、道闸、预约、计费、审计和统计全链路。

### 16.11 计费、预约、审计和分析

`BillingRule` 默认免费 30 分钟、计费单位 30 分钟、最低 2.5、每单位 2.5、日封顶 100；`BillingService::calculateFee(seconds)` 实现向上取整和封顶。

`ReservationService` 的核心函数是 `create`、`cancel`、`checkIn`、`sweep`、`prepareExitSettlement`、`applyExitSettlement`、`rollbackExitSettlement`、`restore`。它在创建时复制车位评估，支付成功后确认，临近开始时短锁，离场时把定金抵扣和停车记录放入同一事务。

`FakePaymentGateway` 提供 `charge/refund/forfeit/failNextCharge`，交易号前缀为 PAY/RFD/FFT；`AuditLogService` 的 `record/recent/verifyChain/hashEntry` 使用前一条 hash 组成 SHA-256 链，改 hash 格式会使历史审计链失效。

`AnalyticsEngine` 的 `snapshot` 汇总容量、收入、平均时长、峰值、预约和 72 小时序列，`fitLinear` 至少需要 3 个样本，`analyze` 预测未来 6 小时。`ParkingInsightEngine::analyze` 按占用、预约、停用权重计算区域压力并生成 30/60/120 分钟风险。`RemoteAnalystClient` 只发送聚合指标；无 endpoint 或 transport 时返回 nullopt。

### 16.12 持久化与账号

`DatabaseManager` 创建唯一 QSQLITE 连接 `smartpark-<this pointer>`；`Persistence::defaultDatabasePath` 依次选择系统数据目录、`~/.smartpark` 和当前目录；`ParkingRepository` 负责 `saveLayout/saveEntry/saveExit/saveSpotState/saveBooking/saveBookingCheckIn/saveReservationOrder/saveReservationCheckIn/saveExitWithReservation` 及对应 load 函数。

Repository 的表包括 parking_spots、parking_records、layout_snapshot、bookings、reservations、deposit_payments。`saveLayout` 用 max_digits10 生成布局签名，布局或车位 ID 不匹配会拒绝启动；`saveExitWithReservation` 原子完成关闭记录、释放车位、完成预约和 Apply 流水。修改 schema 必须同步迁移、保存、加载和恢复校验。



`UserStore` 的 `verifyLogin/registerUser/issueToken/verifyToken/revokeToken/revokeUserTokens/roleOf` 管账号和令牌，另有 `isValidUserName/isValidPassword/lockedRemainderMs` 等校验接口。密码使用 16 字节 salt、12000 轮 SHA-256；连续 5 次失败锁定 10 分钟；令牌只存摘要。修改账号 schema、哈希或锁定规则会影响本地登录、TCP 登录、REST Bearer 和 WebSocket 鉴权。

## 17. 网络层、服务器和现场终端

### 17.1 `src/network/Protocol.h/.cpp`

常量为 `kProtocolVersion=1`、`kMaxFrameBytes=9*1024*1024`、`kMaxImageBytes=6*1024*1024`。`encodeFrame(const QJsonObject&)` 输出四字节大端长度加紧凑 JSON；`tryDecodeFrame(QByteArray&,QJsonObject*)` 返回 `NeedMore/Ok/Invalid`，长度超限或 JSON 无效时为 Invalid。

`makeRequest(action,token,payload,id)` 生成 request，`makeResponse(id,ok,payload,error)` 生成 response，`makeEvent(event,payload)` 生成 event。车型转换支持 car、motorcycle、truck、electric。修改帧、字段或上限必须同步 TcpClient、ServerSession、SmartParkTcpServer、GateApp、UserApp 和 selftest。

### 17.2 `TcpClient.h/.cpp`

`TcpClient : QObject` 保存 `QTcpSocket* socket_`、接收 buffer、按请求 ID 保存的 responses、events、token、lastError 和 requestCounter。公开 `connectToHost(host,port,timeoutMs=5000)`、`disconnectFromHost`、`connected`、`lastError`、`setToken`、`request(action,payload,timeoutMs=5000)`、`takeEvents` 和 `onEvent`。

`request` 发出 cN 请求并用嵌套 QEventLoop 等待 response；`onReadyRead` 循环拆帧，按 id 入响应表，event 入事件队列并调用回调；断开会清 token、buffer 和响应。它适合道闸、用户终端和测试，GUI 使用 ServerSession。修改同步等待或超时要检查 Qt 事件循环和心跳。

### 17.3 `ServerSession.h/.cpp`、`EventHub.h`

`ServerSession` 状态为 `Disconnected/Connecting/LoggingIn/Online`，ReplyHandler 是 `function<void(bool,const QString&,const QJsonObject&)>`。公开 `start(host,port,user,password)`、`stop()`、`request(action,payload,handler)`、`state/host/port/user/hasPendingRequests`，信号为 stateChanged、authFailed、eventReceived。

私有 `establishConnection/authenticate/sendFrame/setState/failPending/scheduleReconnect/onReadyRead/onSocketDisconnected` 实现异步连接；心跳 20 秒，连续失败后断开；重连退避 1 到 15 秒；认证失败 intentionalStop，不重复错误密码；在途写请求断线直接失败，不自动重试。

`EventHub::publish(name,payload,Origin)` 发出 eventOccurred。TCP 来源先直发再 publish，REST 来源转发给 TCP，避免重复事件。改 Origin 或订阅逻辑必须同步两端。

### 17.4 `SmartParkTcpServer.h/.cpp`

`Options` 默认 port 9527、heartbeatTimeoutMs 60000、maxLoginFails 5、lprCommand 为空。每个 Session 保存 socket、buffer、authenticated、user、token、lastSeenMs 和 loginFails。

连接层函数是 `onNewConnection/onReadyRead/onDisconnected/handleMessage/dispatch/send/respond/sendToSessions/broadcastEvent/kickIdleSessions`。动作函数是 `actionLogin/actionStatus/actionSpotList/actionEnter/actionLeave/actionReservationCreate/actionReservationCancel/actionReservationCheckIn/actionAnalyticsReport/actionGateReplay/actionAdminSnapshot`，LPR 由异步 `startLprRecognize` 单独回包。

非 login 请求必须已认证且 token 相同；gate.replay 仅 gate，admin.snapshot 仅 admin。`actionEnter` 调 ParkingService 并广播 parking.entered；`actionLeave` 结算并广播 parking.exited；预约动作广播 created/cancelled/checkin；gate.replay 限 1..500 条，限制时间范围并按 plate+kind+精确毫秒去重；admin.snapshot 输出布局、车位、区域、记录、预约、规则、收入和定金统计。新增 action 必须补权限、payload、错误、事件和测试。

### 17.5 `RestGateway.h/.cpp`、`PlateRecognition.h/.cpp`

RestGateway 默认 HTTP 8080、WebSocket 8081。处理器包括 meta、register/login/refresh/logout、me、status、spots、layout、records、active record、enter、leave、reservations、payment orders、guide、qr、site resolve、plate list/bind 和异步 lpr recognize。辅助函数 `bearerToken/authenticate/bodyJson/errorObject/jsonError` 负责鉴权和错误；`statusPayload/spotListPayload/layoutPayload/routePayload/recordPayload/reservationPayload/orderPayload` 负责输出。

WebSocket 连接先发 `{type:"auth",token}`，认证后仅处理 ping/pong，业务事件由 EventHub 广播。HTTP 非 `/api` 请求服务 webRoot 静态页面并回退 index.html，API 错误为 JSON。

`PlateRecognition` 定义 `LprStatus {Ok,NoPlate,Failed}` 和 `LprOutcome`。`classifyLprOutput` 解析脚本 stdout；`recognizePlate` 是同步入口；`recognizePlateAsync` 用 QProcess、临时图片和 60 秒 watchdog，保证识别不会阻塞服务器。修改输出 JSON、后端命令或超时要同步 Python 脚本、TCP、REST、管理员端和 LPR 测试。

### 17.6 `apps/server/main.cpp`

内部 `HttpProbe::send` 用于 selftest 的 HTTP 探测，`freePort` 选择可用端口，`runSelftest` 覆盖 TCP、LPR、REST、WS、二维码、补报和审计；`runServer` 创建 Persistence、AuditLogService、UserStore、ParkingService、EventHub、SmartParkTcpServer 和 RestGateway；`main` 解析 `--port/--db/--layout/--http-port/--ws-port/--advertise/--ws-public-url/--web-root/--lpr-command/--site-name/--selftest`。

改变启动参数要同步 README、部署文档、CTest E2E 和管理端远程连接默认值。服务器是所有远程数据的唯一业务入口，不应让管理端绕过它直接写数据库。

### 17.7 `apps/gate`

`BarrierGate` 状态为 Closed/Opening/Open/Closing/Fault，定时为开启 700ms、保持 5000ms、关闭 700ms、故障告警 4000ms。公开 `requestOpen/vehiclePassed/setFault/reset/state/antiSmashCount/stateText`，内部 transition/startOpening/startHold/startClosing/startFaultAlarm/cancelTimer。

`GateClock` 抽象 `schedule(milliseconds,Callback)/cancel/now`；`VirtualGateClock` 提供 `advance/advanceToNextTimer/pendingTimers`，`QtGateClock` 用 QTimer 实现真实计时。两种实现必须保持同一接口。

`OfflineQueue` 提供 `append(QJsonObject)/pending(limit=500)/acknowledge(count)/size`，以及 `replayHandledPrefix/replayBatchHandled/replaySkippedDetails`。JSONL 追加后 flush，确认使用 QSaveFile 删除前缀；只有连续有 verdict 的结果可以出队，skipped 也算已处理，截断响应后的后缀保留。修改它必须同步 SmartParkTcpServer::actionGateReplay。

`GateApp` 负责 5 秒重连、20 秒心跳、登录、flushQueue、recordOffline、handleEntrance、handleExit。在线入口发 parking.enter，出口发 parking.leave；离线时先写队列，写入成功才放行。改命令行参数或 JSON 字段要同步 server。

### 17.8 `apps/user/main.cpp`

`UserApp` 保存 TcpClient、重连和心跳定时器，提供 `start/log/tryConnect/printStatus/handleCommand`。命令 status 发 parking.status，reserve 计算开始时间和时长后发 reservation.create，cancel 发 reservation.cancel。断线只提示重连，不提供离线预约。改用户端命令必须同步 TCP server action。

## 19. 脚本与测试的代码级入口

### 19.1 车牌识别脚本

`scripts/recognize_plate.py` 的 `parse_args` 处理 image、detector、recognizer、config、paddleocr、ocr-python、dictionary、confidence、crop、recipe、flip-check；`recognize` 完成 YOLO CPU imgsz=960 检测、最高置信框、OBB/关键点四角、auto/quad/bbox 裁剪和 PaddleOCR；检测器不给框而输入本身是裁好的车牌时改走 `recognize_whole_image`（`plate_like_frame` 校验宽高比与最小高度，要求识别置信度 ≥0.9），结果标记 `crop=whole`、`quad_source=none`、`detection_confidence=null`；`main` 输出单行 JSON。`valid_plate` 用正则检查车牌格式。输出包括 plate、detection_confidence、recognition_confidence、bounding_box、valid、crop、crop_image、quad_source、flip_checked、recipe、color、color_confidence、new_energy。

`plate_geometry.py` 定义冻结的 `CropRecipe(mode='quad',height=64,min_width=160,max_width=320,expand=.06,quality=95)`；`order_quad/ccpd_quad/expand_quad/rectified_size/rectify/clip_bounds/crop_box/prepare_crop/write_crop` 共同保证训练与推理的几何一致。改它必须重跑黄金像素测试并考虑旧模型输入分布。

`lpr_service.py` 的 ResidentEngine 持有 YOLO 和 PaddleWorker；RequestHandler 只接受 `{image:string}`，请求上限 8192B；serve 绑定 Unix socket，warmup 不输出样例 crop，watch_parent 每 0.5 秒检查父进程。`lpr_ocr_worker.py` 缓存 OCR 初始化函数但每张图重新推理；stdout 只能输出 JSON，日志写 stderr。`lpr_client.py` 只对 ENOENT/ECONNREFUSED 重试，不回退 mock。

`lpr_runtime_cache.py` 的 `prepare` 生成受控实体缓存，`_owned` 防 root 逃逸/软链接，`_lock` 用 flock，`_atomic` 负责 fsync+replace。该模块当前 opt-in，常驻主文件没有自动调用它，集成时要明确调用方。

### 19.2 数据准备、训练和评测

`prepare_ccpd.py` 的 `parse_args/main` 支持 det/obb/pose、CCPD2019/2020、green-only、下载开关，输出图片、标签和 yaml；哈希分割影响复现和数据泄漏口径。`prepare_recognition.py` 的 `parse_args/main` 读取文件名车牌和四点框，调用共享 crop，输出 train/val/test、字典、recipe 和 SUMMARY，输出目录会重建。

`prepare_recognition_focus.py` 按省份规划重复倍数，`prepare_recognition_green.py` 过滤绿色车牌并按比例重复；两者共享 focus/base 数据布局。`train_lpr.py` 对 det/obb/pose 调 Ultralytics，默认 epoch=100、imgsz=960、batch=16；`train_rec.py` 调 PaddleOCR，默认 epoch=20、batch=64、lr=.0002，并支持续训和多卡。

`evaluate_plates.py` 的 `evaluate_one/init_worker/main` 输出逐图 JSONL；默认检测和识别权重与部署默认 pose+均衡配置不同，`--base` 当前实现仍有固定目录依赖，且识别失败统计不会让 main 非零退出。`benchmark_lpr.py::compare/main` 比较单图和常驻结果，置信度漂移超过 `1e-6` 或新增错误则 exit 1。`curate_plate_examples.py` 按 manifest 整理 40 张集成样例。

## 22. 顶层文件和构建文件

### `CMakeLists.txt`

### `handoff.md`

历史交接说明，记录旧命令、历史测试和迁移注意事项。它不被程序读取，作用是帮助维护者判断旧文档是否仍有效。改代码后如果旧命令失效，应在这里记录迁移方向，而不是让它继续被当成当前接口。

### `.gitignore`、`.gitattributes`

`.gitignore` 排除 build、数据库、模型、训练结果和本地环境；`.gitattributes` 约束文本/二进制的 Git 属性。误删 ignore 规则会把权重、数据库或训练产物加入版本库，误改文本规则可能造成布局或 JSON 换行变化。

## 23. `src` 中的每一个实现文件

### `src/core/CMakeLists.txt`

把 model、service、persistence 的所有 `.cpp/.h` 组成 `smartpark_core` 静态库，公开 `src` include 路径并链接 Qt6::Sql。新增核心文件而不加到此处，文件不会进入目标；删除源文件名会造成链接缺失。

### `src/core/model/Geometry.h`

只含几何基础类型和 inline 函数，见前文 16.1。没有对应 `.cpp`，因此改动会直接重新编译所有 include 它的目标。

### `src/core/model/Vehicle.h`、`Vehicle.cpp`

头文件定义 VehicleType 和 Vehicle 接口；cpp 实现构造校验和访问函数。它是模型、协议、持久化和 UI 的交汇点，车型新增必须跨层迁移。

### `src/core/model/ParkingSpot.h`、`ParkingSpot.cpp`

头文件定义 SpotStatus、SpotType、Geometry、状态查询和状态改变接口；cpp 实现 occupy/reserve/expire/release/disable 的合法迁移。所有停车位变化最终都经过它，禁止在页面中直接改 status。

### `src/core/model/ParkingRecord.h`、`ParkingRecord.cpp`

头文件定义记录字段和 close/duration 接口；cpp 实现时间、费用和关闭合法性。计费错误、离场时间异常和重启后活动记录校验都从这里开始排查。

### `src/core/model/Booking.h`、`Booking.cpp`

头文件定义旧式 BookingStatus、BookingPolicy 和 Booking 接口；cpp 实现传统预约状态机。它目前主要作为历史预约兼容层和旧接口数据，不要把新版 Reservation 的定金状态直接塞进这里。

### `src/core/model/Reservation.h`、`Reservation.cpp`

定义新版时段预约、定金流水、ExpectedRoute 和状态转换。cpp 负责参数检查、状态迁移、路线编码解码。任何字段变化必须同步 Repository 的 reservations/deposit_payments、TCP/REST 输出和管理端 Booking 页面。

### `src/core/model/ParkingLayout.h`、`ParkingLayout.cpp`

头文件定义布局公开构造/读取接口和 AisleSide；cpp 实现 DSL 解析、区域生成、障碍检查、默认布局和内置车库布局。改动会影响布局签名，因此已有数据库可能被拒绝启动。

### `src/core/util/TimeUtil.h`

提供业务时间的合法范围、`isValid`、`canAdd`、`toMilliseconds`、`fromMilliseconds`。它是 SQLite 时间转换边界；改范围可能让旧记录无法恢复，改毫秒转换会影响所有计费、预约和排序。

### `src/core/service/Billing.h`、`Billing.cpp`

BillingRule 和 BillingService，核心函数 `calculateFee`。这里只做费用计算，不写数据库、不处理支付。需要更改价格时优先改此处和测试，不要在 UI 或 REST 里复制计算公式。

### `src/core/service/GridPlanner.h`、`GridPlanner.cpp`

定义 Route、OccupancyField 和网格搜索。cpp 的关键私有函数是 `cellIndex/cellCenter/isFree/nearestFreeCell/occupancyMultiplier/searchFrom/searchFromGoals/reconstruct`。改搜索代价会改变所有推荐路线；改网格边界要重点测试障碍物贴边和对角穿越。

### `src/core/service/SpotAllocator.h`、`SpotAllocator.cpp`

定义分配策略、权重、分数拆解和 AllocationProposal。cpp 的关键函数是 `evaluateCandidates/exitCoefficient/makeScore/typePenaltyFor/nearbyOccupiedSpots`。它不负责占用车位，只负责推荐；真正状态修改由 ParkingService 完成。

### `src/core/service/ParkingService.h`、`ParkingService.cpp`

聚合根和交易编排器。头文件定义 AllocationResult、BookingResult、CarFinderResult 和所有业务入口；cpp 实现入场、离场、预约、应急驱逐、持久化回滚、恢复和统计。修改它前要画清“内存状态—数据库事务—审计”的顺序。

### `src/core/service/ReservationService.h`、`ReservationService.cpp`

管理新版预约和定金。头文件定义 ReservationResult、ExitSettlement 和 create/cancel/checkIn/sweep/settlement/restore；cpp 实现时间窗口、延迟锁位、支付失败、未到场、离场抵扣和回滚。它是 ParkingService 的 friend，改 ParkingService 私有成员布局可能需要同步这里。

### `src/core/service/FakePaymentGateway.h`、`FakePaymentGateway.cpp`

定义 charge/refund/forfeit/failNextCharge，生成演示交易号。它不连接真实支付平台，专门用于可重复测试；将来接真实支付时应保持 ReservationService 的接口边界，不把第三方 SDK 直接塞入模型。

### `src/core/service/AuditLogService.h`、`AuditLogService.cpp`

定义审计 Entry、VerifyResult 和 record/recent/verifyChain/hashEntry。cpp 创建 audit_logs、追加前 hash、回填当前 hash。改 hash 拼接格式会使历史审计链全部变为不可信，应设计版本字段或迁移。

### `src/core/service/AnalyticsEngine.h`、`AnalyticsEngine.cpp`

定义 OccupancySample、OperationalSnapshot、LinearTrend、AnalysisFinding、AnalysisReport。cpp 从 ParkingService 读取只读数据，执行 72 小时 OLS 和 6 小时预测。改 snapshot 字段需要同步 Dashboard、RemoteAnalystClient 和 admin.snapshot。

### `src/core/service/ParkingInsightEngine.h`、`ParkingInsightEngine.cpp`

定义 ZoneInsight、OccupancyForecast、RiskAlert、ParkingInsights，只有静态 `analyze` 入口。它产生提醒，不改变交易状态；调整阈值应补洞察测试并检查 Dashboard 文案。

### `src/core/service/RemoteAnalystClient.h`、`RemoteAnalystClient.cpp`

定义 RemoteAnalystConfig、Transport 和 analyze/buildRequestJson/parseResponse。它发送聚合指标，不发送车牌图片或单车敏感信息。没有 endpoint/transport 时安全返回空结果。

### `src/core/service/UserStore.h`、`UserStore.cpp`

定义登录结果、注册结果、TokenIdentity 和账号接口；cpp 管 users/auth_tokens 表、迁移、密码摘要、失败锁定和令牌撤销。它使用独立 SQLite connection，但文件与停车数据相同；不要通过 ParkingRepository 读写 users。

### `src/core/service/DemoDirector.h`、`DemoDirector.cpp`

定义演示步骤和虚拟时钟剧本，`step` 依次驱动入场、预约、爽约、核销、离场和分析。它只为演示调用公开服务接口，改它不会改变正式停车逻辑，但会改变答辩演示顺序。

### `src/core/persistence/DatabaseManager.h`、`DatabaseManager.cpp`

RAII 管理唯一 QSQLITE connection，提供 database 和 lastError，禁止拷贝移动。改连接名、析构顺序或错误处理会影响 Repository、Persistence、UserStore 的生命周期。

### `src/core/persistence/Persistence.h`、`Persistence.cpp`

提供默认数据库路径和 Repository 所有权。构造时打开数据库并建表，失败抛异常。改默认路径会影响 GUI、server、测试和用户查找历史数据的位置。

### `src/core/persistence/ParkingRepository.h`、`ParkingRepository.cpp`

定义 PersistedSpotState、PersistedRecord 和所有 save/load。cpp 建表、迁移、生成 layout signature、校验跨对象不变量并包裹事务。它是停车数据唯一持久化边界，任何新增业务状态最终都要落到这里。

### `src/network/CMakeLists.txt`

把 EventHub、Protocol、TcpClient、ServerSession、PlateRecognition、RestGateway、SmartParkTcpServer 和 QR generator 编译为 `smartpark_network`，链接 core 和 Qt Network/HttpServer/WebSockets。新增网络类不加入源清单就不会被构建。

### `src/network/Protocol.h`、`Protocol.cpp`

定义协议版本、帧大小、FrameStatus、请求/响应/event 工厂和车型转换。cpp 实现大端长度帧。任何协议改动必须先列出所有发送方和接收方。

### `src/network/TcpClient.h`、`TcpClient.cpp`

同步终端客户端，维护 response map 和 event vector。适用于 gate/user/selftest，不适合长期 GUI 操作，因为 request 使用嵌套事件循环。

### `src/network/ServerSession.h`、`ServerSession.cpp`

异步 GUI 会话，负责状态机、心跳、退避重连、认证失败停机和 pending 失败。不要给它增加自动重试写请求，除非同时引入幂等 request ID 机制。

### `src/network/EventHub.h`

只有轻量 Qt signal hub 和 Origin 枚举；它本身不保存业务状态。重复广播问题通常应从 Origin 判断和订阅方向排查。

### `src/network/PlateRecognition.h`、`PlateRecognition.cpp`

定义 LprStatus、LprOutcome、同步/异步识别和 mock。cpp 负责脚本进程、临时文件、60 秒 watchdog、stdout JSON 分类和 context 生命周期。改执行方式要防止子进程卡住主线程。

### `src/network/SmartParkTcpServer.h`、`SmartParkTcpServer.cpp`

定义 Session、Options、连接读写、认证、所有 action、admin snapshot 和 gate replay。它是 TCP 外部输入的安全边界，新增字段必须做空值、权限、长度和错误检查。

### `src/network/RestGateway.h`、`RestGateway.cpp`

定义 HTTP/WS Options、订单和 WS session，提供所有 REST handler、鉴权、payload、订单 schema、事件广播和静态文件回退。REST 与 TCP 共用 ParkingService，不能在 REST 层重新实现停车规则。

Login 定义本地/远程模式、记住账号、Keychain 密码、远程临时 ServerSession、失败提示和本地五次锁定；Register 负责字段校验、密码强度、UserStore::registerUser 和注册后回填。远程失败不会走本地锁定分支。

### `MainWindowController.*`、`SidebarViewController.*`

MainWindow 创建七页和共享 bridge，按远程能力隐藏页面并广播 refresh；Sidebar 负责可见索引映射、选择、账号显示和退出。修改页序要改两处数组和映射。

### 七个页面控制器

`DashboardViewController.*` 从 DataSource 取 KPI、图表、预测和洞察；`ParkingMapView.*`/`ParkingMapViewController.*` 做坐标变换、绘制、hover 和路线显示；`OperationsViewController.*` 做入离场、车型、策略、应急和本机 LPR；`OccupancyViewController.*` 做双列表车位视图并发送车辆选择通知；`BookingViewController.*` 做新版 Reservation；`RecordsViewController.*` 做时间重叠筛选；`SettingsViewController.*` 做布局文本解析、应用、重置、导入导出。页面不应直接操作 SQLite 或修改核心对象字段。

### 图表、工具和识别文件

`DonutChartView.*` 定义 DonutSliceData 和环图；`BarChartView.*` 定义 BarSliceData 和柱图；`LineChartView.*` 定义 LinePointData/LineSeriesData 和折线图；它们只绘图。

`TableView.*` 定义列、行、徽章和选择回调，控制器负责业务筛选；`TextUtil.h` 提供车型、车位、状态文本和时间格式；`RecognitionConfidence.h` 的 `needsConfirmation` 只检查 valid 和识别置信度；`PlatePhotoArchive.*` 管理照片目录、文件名、按车牌查询和最新照片；`LocalRecognitionService.*` 是单例 NSTask 常驻服务、预热、停止和 generation 防旧任务覆盖。

### `apps/macos/bridge/ParkingDataSource.h`

定义本地/远程共用抽象：Capabilities、ReservationRuleView、PlateRecognition、ReservationCreation、数据 getter、统计、识别、入离场、预约和布局编辑。它是页面与实现之间的契约，不能为了某个页面随意改默认能力。

### `ParkingBridge.*`

持有本地 Persistence/ParkingService 或 RemoteDataSource，负责 rebuildService、布局应用、清业务数据、plannedRoute、pendingReservations、统计、入离场、车型、策略、预约和事件。它不是第二套业务层，而是 UI 适配层。

### `RemoteDataSource.*`

继承 QObject 和 ParkingDataSource，持有 ServerSession 和 admin.snapshot 缓存。`applySnapshot` 把 JSON 还原为 ParkingLayout、ParkingSpot、ParkingRecord、Booking、Reservation；事件到达后重新拉快照。远程不支持 emergency/type/strategy/layout 写入。修改快照字段必须同步 server actionAdminSnapshot。

## 25. `scripts` 中的每一个文件

### 车牌主链

`recognize_plate.py`：入口 `parse_args/recognize/main`，处理检测、四角、裁剪、OCR 和 JSON 输出；`plate_geometry.py`：入口 `CropRecipe/from_mapping/load/save/order_quad/ccpd_quad/expand_quad/rectified_size/rectify/crop_box/prepare_crop/write_crop`，是训练和推理共用几何。

`lpr_service.py`：`ResidentEngine/PaddleWorker/RequestHandler/serve/warmup/watch_parent/main`，把 YOLO 和 OCR 变成 Unix socket 常驻服务；`lpr_ocr_worker.py`：`cache_once/cache_initializers/main`，缓存初始化但每图重新推理；`lpr_client.py`：`connect/request/main`，连接常驻服务且不回退 mock；`lpr_runtime_cache.py`：`prepare/_metadata/_owned/_lock/_atomic`，建立受控模型缓存，目前 opt-in。

### 数据准备和训练

### 评测和样例

`evaluate_plates.py` 的 `parse_args/evaluate_one/init_worker/main` 逐图输出 JSONL；`benchmark_lpr.py` 的 `compare/main` 比较基线和常驻输出；`curate_plate_examples.py` 的 annotated_plate/source_path/selected_entries/main 整理并校验 40 张样例。

### Shell/Slurm 文件

## 28. 不属于业务源文件的目录

`build/`、`build-rest/` 是 CMake 生成物，包含 moc、编译缓存和可执行文件，不能当作源码修改；重新 configure/build 会覆盖它们。`.mimosa/` 是本地工具状态。各目录 `.DS_Store` 是 Finder 元数据。`third_party/PaddleOCR.evicted2/` 是外部 OCR 工程备份，SmartPark 通过脚本调用外部 PaddleOCR，不把它作为核心业务库编译；改其中文件不会自动改变 SmartPark，除非外部运行环境明确引用了它。

## 29. 一次修改应如何落地

先确定修改属于模型、规则、持久化、协议、UI、脚本还是测试；然后从该文件向上查调用者，向下查保存/输出边界。例如增加车位状态，要改 ParkingSpot、Repository、Protocol/REST、地图和状态测试；增加管理员按钮，要先确认 ParkingDataSource 在本地和远程是否都有能力，再改 Bridge、RemoteDataSource、MainWindow/Sidebar、页面和测试；调整 LPR 裁剪，要同时改 plate_geometry、训练数据、推理脚本、runtime service、模型 recipe 和几何/常驻测试。

最终闭环永远是：输入文件或用户操作 → 解析/协议 → ParkingService 或脚本主函数 → 模型状态 → Repository 或评测 JSON → EventHub/页面或报告。只改其中一层通常会造成“界面显示新字段、服务器仍发旧字段”“数据库能保存、重启不能恢复”或“单图能识别、常驻服务输出被日志污染”等问题。
